# ממשק עברית (RTL) ל-Claude Code — גרסת פרימיום

ממשק גרפי מלא סביב כלי הטרמינל `claude`. מאחורי הקלעים רץ אותו Claude Code
שאתה כבר משתמש בו (במצב `stream-json`), והממשק מוסיף שכבת חוויית-משתמש מלאה עם
תצוגה נכונה מימין-לשמאל.

## הפעלה

```bash
cd ~/rtl-claude
npm start          # ואז פותחים http://localhost:4173
```

כדי להריץ גם את שער המודלים המקומי (OmniRoute) באותה פקודה:

```bash
npm run dev:all    # מרים את OmniRoute ב-Docker וממתין לו, ואז את השרת
```

ראו [ספקי מודלים](#ספקי-מודלים).

או פשוט לוחצים על הקיצור **"Claude · ממשק עברית"** בשולחן העבודה (או בתפריט האפליקציות) —
הוא מרים את השרת אוטומטית אם צריך ופותח את הדפדפן (`launch.sh`).

השרת מאזין על `127.0.0.1` בלבד. בנוסף עולה מאזין על כתובת ה-LAN של המחשב
(פורט `PORT+1`) — פתוח רק למכשירים מקושרים. ראו
[חיבור מכשיר קבוע](#חיבור-מכשיר-קבוע-lan).

## פיצ'רים

### תצוגה וכיווניות
- **BIDI מדויק** — כל פסקה מקבלת כיוון לפי התו החזק הראשון שלה. עברית לימין,
  אנגלית וקוד לשמאל, גם כשהם מעורבים באותה שורה.
- **סטרימינג בזמן אמת** — הטקסט מופיע מילה-מילה תוך כדי כתיבה (`--include-partial-messages`).
- **הדגשת תחביר** לקוד + כפתור העתקה בכל בלוק.
- **דיאגרמות mermaid** מרונדרות אוטומטית.
- **כרטיס חשיבה** — נפתח בלחיצה ומציג את החשיבה תוך כדי סטרימינג.
  מודלים חדשים (Opus 5 ומעלה) לא מחזירים את שרשרת החשיבה הגולמית: כברירת מחדל
  בלוק ה-thinking מגיע עם `signature` בלבד וללא טקסט. לכן השרת מריץ את ה-CLI עם
  `--thinking-display summarized`, שמבקש תקציר קריא של החשיבה — וזה מה שמוצג בכרטיס.
  אם ה-CLI המותקן ישן מכדי להכיר את הדגל, השרת מזהה זאת בהרצה הראשונה, ממשיך
  בלעדיו, והכרטיס מציג במקום זאת כמה טוקני חשיבה הוקדשו.
- **מצב בהיר/כהה** — לפי המערכת, עם כפתור החלפה ידני.

### כרטיסי כלים עשירים
כל פעולה של Claude מוצגת ככרטיס מתקפל עם סטטוס (רץ / הושלם / שגיאה):
- **Bash** — פקודה + פלט בסגנון טרמינל
- **Edit / MultiEdit** — תצוגת **diff** צבעונית (מה נמחק / מה נוסף)
- **Write** — הקובץ והתוכן
- **Read** — הקובץ שנקרא
- **TodoWrite** — רשימת משימות עם סימוני ☑ / ◐ / ☐
- שאר הכלים — קלט ותוצאה מפורמטים

### שיחות וזיכרון
- **ריבוי שיחות** בסרגל צד, עם כותרות אוטומטיות.
- **המשכיות מלאה** — כל שיחה שומרת `session_id` וממשיכה עם `--resume`,
  כך שההקשר נשמר גם אחרי רענון הדף או מעבר בין שיחות.
- **אחסון קבוע בדיסק** — כל שיחה היא קובץ JSON נפרד תחת
  `~/.claude/rtl-claude/conversations/`, נכתב אטומית (tmp + rename).
  הכל נשאר על המחשב, ואין שום מגבלת גודל.
  - באתחול נטען רק **אינדקס** (כותרות + מטא), ולכן הפתיחה מיידית גם עם מאות שיחות;
    גוף השיחה נקרא מהדיסק רק כשנכנסים אליה.
  - שמירה מושהית של מה שהשתנה בלבד, ושמירה סופית ב-`sendBeacon` בסגירת החלון.
  - בזמן תור חי נשלחת **רק ההודעה האחרונה** (`fromIndex`) — היא היחידה
    שמשתנה, והשרת משאיר את הקידומת שבדיסק במקומה. מה שמתיר את זה הוא בדיקת
    הגרסה (`rev`): גרסה זהה בדיסק פירושה שהקידומת שם היא בדיוק זו שבדפדפן.
    בסוף התור נשלחת שמירה מלאה אחת. בלי זה כל שמירה, כל 2.5 שניות, סידרה
    ושלחה וכתבה את התמליל *כולו* — עלות שגדלה עם אורך השיחה.
  - **כישלון שמירה נראה לעין** — חיווי אדום בסרגל העליון וניסיון חוזר.
- **טיוטות** — טקסט שהוקלד ולא נשלח נשמר עם השיחה. יציאה וכניסה לא מוחקות אותו.
- **תיקיית עבודה לכל שיחה** — נזכרת בנפרד ומוצגת תמיד בסרגל העליון,
  כדי שלא תריץ פקודות בפרויקט הלא נכון.
- **שיחה ללא תיקייה** — מתג בהגדרות (מתחת לשדה התיקייה) שמחליף את הפרויקט
  בשיחה פשוטה מול המודל: בלי כלים, בלי גישה לקבצים ובלי הרשאות. ראו
  [שיחה ללא תיקייה](#שיחה-ללא-תיקייה).
- **חיפוש בכל השיחות** — הסרגל סורק בשרת גם את גוף השיחות שלא נטענו, ומציג קטע
  הקשר. האינדקס ממוטמן לפי חתימת הקובץ (mtime + גודל), כך שרק שיחה שהשתנתה
  נקראת שוב — אחרת כל הקלדה בסרגל הייתה עוצרת את הסטרימינג לפענוח של הכל.
- **ייצוא ל-Markdown** (Ctrl+E) ו**חיפוש בתוך השיחה** (Ctrl+F).

> **הערה על שדרוג מגרסה קודמת:** ההיסטוריה שנשמרה ב-`localStorage` מהוגרת
> אוטומטית לדיסק בפתיחה הראשונה (ומוצגת הודעה כמה שיחות הועברו). הסיבה למעבר:
> `localStorage` מוגבל ל-~5MB, הכתיבה נכשלה בשקט כשהמכסה התמלאה — ומאותו רגע
> שיחות חדשות פשוט לא נשמרו.

### צ׳אט אנונימי — שיחה שלא נשמרת בשום מקום

כפתור **"צ׳אט אנונימי"** בסרגל הצד (או `/anon`) פותח שיחה שמתנהגת כמו כל שיחה
אחרת — ולא משאירה אחריה כלום. היא נמחקת ברגע שיוצאים ממנה, סוגרים את החלון או
מאבדים את החיבור למשך יותר מדקה.

**"יציאה" = כל דרך לצאת.** לא רק כפתור היציאה: מעבר לשיחה אחרת מהרשימה או
מלוח הפקודות, "שיחה חדשה", "דואט חדש", המשך סשן מהדיסק, או קפיצה לשיחה
שממתינה לאישור — כולן מוחקות אותה מיד. אין מצב שבו עוזבים אותה והיא ממתינה
ברקע לחזרה, כי שיחה שאפשר לחזור אליה היא שיחה ששרדה. אם יש בה כבר הודעות
תישאל שאלת אישור אחת; ביטול משאיר אותך בתוכה, אישור מוחק בלי דרך לשחזר.

מה בדיוק מנוטרל, אחד-אחד:

| המנגנון הרגיל | מה קורה בצ׳אט אנונימי |
| --- | --- |
| קובץ שיחה ב-`~/.claude/rtl-claude/conversations/` | לא נוצר. הכתיבה נדחית גם בדפדפן וגם בשרת (403), ו-`writeConv` זורק אם בכל זאת הגיע לשם מזהה אנונימי |
| קובץ סשן של ה-CLI ב-`~/.claude/projects/…jsonl` | ה-CLI רץ עם `--no-session-persistence` ולא כותב אותו. ממילא אין `--resume`, והוא נחסם במפורש |
| יומן הריצה (`rtl-claude.log`) | אף שורה. `dbg` בולע כל רשומה שנושאת מזהה אנונימי, והדפדפן לא שולח שורות יומן כלל כל עוד צ׳אט כזה פתוח |
| היסטוריית הפרומפטים (חץ למעלה) | לא נרשמת — היא נשמרת בקובץ ההגדרות, כלומר בדיסק |
| כותרת אוטומטית מההודעה הראשונה | לא נגזרת. הכותרת קבועה, כדי שתוכן השיחה לא יופיע ברשימה הצדדית ובכותרת החלון |
| `activeId` בקובץ ההגדרות | נכתב `null`. גם "היה פתוח צ׳אט אנונימי בשעה הזו" היא עקבה |
| עותק זמני של תמונה שהודבקה ב-`/tmp` | לא נכתב. התמונה מגיעה למודל כ-base64 בלבד |
| `pending-resume.json` (המתנה לחידוש מכסה) | לא נכלל. צ׳אט אנונימי לא שורד הפעלה מחדש של השרת — זו התכונה, לא התקלה |
| טלמטריה, דיווח שגיאות וקריאות מודל נלוות | מכובים בסביבת התהליך |

**הכלים כבויים כברירת מחדל.** `Bash` ו-`Edit` משאירים עקבות משל עצמם — קבצים
שהשתנו, גיבויי `file-history`, תמונות shell — ואלה כבר לא בשליטת המצב הזה.
אפשר להדליק אותם במתג שבפס העליון, אבל רק **לפני** ההודעה הראשונה: הדגל נקבע
בשורת הפקודה של התהליך, והתהליך הוא ההקשר של השיחה.

**ההקשר חי בתהליך בלבד.** אין קובץ סשן לחזור אליו, ולכן: אין "חזרה לנקודה
קודמת", אין המשך אחרי הפעלה מחדש של השרת, ואי-אפשר להחליף רמת מאמץ או ספק
באמצע (החלפת מודל באותו ספק כן עובדת — היא נעשית בתוך אותו תהליך).

**מה שלא מובטח, במפורש:** הבקשות עצמן יוצאות ל-Anthropic (או לספק שנבחר) כמו
בכל שיחה, וכפופות למדיניות שלהם; השימוש נספר במכסת החשבון; זיכרון התהליך עלול
להיכתב ל-swap של מערכת ההפעלה; ו-JavaScript לא מאפשר לדרוס מחרוזת בזיכרון —
"נמחק" כאן פירושו שאין אליה יותר הפניה והיא משוחררת. "אנונימי" כאן =
**לא נשמר אצלנו, לא ב-CLI, ולא ביומן**.

שני דברים שה-CLI עצמו נוגע בהם בכל הרצה, גם אנונימית, ונבדקו אחד-אחד: בזמן
שהתהליך חי הוא רשום ב-`~/.claude/sessions/<pid>.json` (pid, תיקייה, גרסה —
בלי תוכן שיחה), והרשומה נמחקת כשהוא נסגר; ו-`~/.claude.json` מתעדכן בחותמות
זמן ובמטמון הגדרות. שניהם מעידים ש*הורצה* פקודה, בלי שום דרך לדעת מה נאמר בה,
והם זהים לחלוטין לכל הרצה אחרת של Claude Code על המחשב.

הכפתור נדלק רק אם ה-CLI המותקן מכיר את `--no-session-persistence`. אם לא —
הוא מוצג כבוי עם הסבר, במקום להריץ שיחה "אנונימית" שנשמרת בדיסק.

### דואט — שני מודלים על תוצר אחד

מצב שבו שני מודלים **לא מתווכחים ולא משוחחים** — הם עובדים לסירוגין על אותו
טקסט. אחד כותב גרסה, השני קורא אותה, מאמץ מה שנכון בה, משפר ומחזיר. זה עט אחד
שעובר בין שתי ידיים, לא שני מונולוגים במקביל. מודל שלישי **מפקח**: הוא לא כותב
את התוצר ולא מדבר אליך, אלא קורא אחרי כל תור ומחליט אחת משלוש — לשתוק, לתת
הכוונה קצרה, או להכריז שהעבודה נגמרה.

- **הגדרה**: מטרה חופשית, שלושה בוררי מודל (כולל ניתוב בין הספקים — אפשר להריץ
  כל משתתף על ספק אחר), תקרת תורות (2–30, ברירת מחדל 8), ותוצר פתיחה לא-חובה.
- **פרוטוקול התוצר**: כל תור מחזיר `CHANGELOG:` (עד חמש נקודות, כל אחת שינוי
  אחד ולמה) ואת התוצר **המלא** בין `<<<ARTIFACT` ל-`ARTIFACT>>>`. החלפה מלאה
  ולא טלאים — פשוט יותר, ובלי כשלים של החלת diff. פורמט שבור מקבל בקשה חוזרת
  אחת; אם גם היא נכשלת הריצה נעצרת עם שגיאה גלויה ולא בולעת את התור.
- **הקשר**: לכל משתתף סשן CLI משלו (`--resume`), כך שהוא זוכר את ההיגיון של
  עצמו לאורך הריצה. למרות זאת התוצר המלא נשלח בכל תור — הוא מקור האמת, לא
  היסטוריית השיחה.
- **מסך הריצה**: התוצר החי למעלה (Markdown, BIDI, בורר גרסאות לצפייה אחורה),
  מהלך העבודה למטה — כרטיס לכל תור עם היומן והתשובה המלאה, והמפקח כנתיב צר
  ביניהם: שתיקה היא סימן דק, הכוונה היא הערה, וסיום הוא כרטיס.
- **בקרה תוך כדי**: השהיה, המשך, עצירה מיידית, ו**הערה משלך** שנכנסת לתור הבא
  בדיוק כמו הערת מפקח ומסומנת ככזו. השהיה ועצירה נכנסות לתוקף **לפני** הקריאה
  הבאה למודל, לא אחריה.
- **סיום מעצמו**: המפקח מכריז `complete` או `stalled`, ובנוסף יש גיבוי
  דטרמיניסטי — שתי גרסאות רצופות עם טקסט זהה הן עצירה עובדתית. תקרת התורות היא
  רשת ביטחון, לא הדרך הרגילה שבה ריצה נגמרת.
- **גבולות**: תקרת גודל לתוצר (200KB — הריצה מסרבת לגדול מעבר לה ומודיעה על כך
  למפקח), חשבון עלות לכל הריצה ולפי משתתף (שלושה מודלים על פני עשרות תורות זה
  יקר, ולכן זה מוצג), וללא כלים — התוצר הוא טקסט במצב הריצה ולא קבצים בדיסק.
- **הריצה חיה בשרת**: רענון דף, מעבר לשיחה אחרת או נעילת הטלפון לא עוצרים אותה,
  והחזרה מציגה בדיוק את מה שקרה בינתיים. הריצה נשמרת כקובץ שיחה עם
  `mode: "duet"` — כל גרסה, כל יומן שינויים וכל הערת מפקח.

### שיחה ללא תיקייה

לא כל שיחה היא עבודה על קוד. המתג **"ללא תיקייה — שיחה פשוטה עם המודל"**
(בהגדרות, מתחת לשדה תיקיית העבודה) מכבה את הצד של הפרויקט:

- **אין כלים** — ההרצה יוצאת עם `--tools ''` ועם הנחיית מערכת שמסבירה למודל
  שאין לו כלים, כדי שלא ימציא קריאות-כלי כטקסט. אין Bash, אין קריאה/כתיבה של
  קבצים, אין בקשות הרשאה.
- **אין פרויקט** — `@` לא מציע קבצים ו-`/` לא מציע פקודות פרויקט, כי אין תיקייה
  לסרוק.
- **השיחה נשמרת כרגיל** — זה ההבדל מ[צ׳אט אנונימי](#צאט-אנונימי--שיחה-שלא-נשמרת-בשום-מקום): ההיסטוריה,
  הכותרת ו-`--resume` עובדים בדיוק כמו בכל שיחה אחרת. מתחת למכסה ההרצה יושבת
  בתיקייה ריקה ייעודית (`~/.rtl-claude/chat`) שכל תפקידה לתת לתהליך מקום לעמוד
  בו וכתובת יציבה לקובץ הסשן.

המתג הוא לכל שיחה (כמו תיקיית העבודה עצמה), מסתנכרן בין המכשירים, והכיבוי
מחזיר את הנתיב הקודם. הצ׳יפ בסרגל העליון מציג "ללא תיקייה" במקום נתיב.

### בקרות
- בחירת **תיקיית עבודה** (עם ולידציה חיה) או **שיחה ללא תיקייה**, **מודל**,
  **רמת מאמץ חשיבה** (נמוך→מקסימלי), ו**מצב הרשאות**.
- **החלפת מודל באמצע שיחה, בלי לאבד את ההקשר.** בוחרים מודל אחר וממשיכים —
  אין הודעה, אין המתנה, אין שיחה חדשה. מאחורי הקלעים: החלפה בתוך אותו תהליך
  (`set_model`), ובשינוי שמחייב הפעלה מחדש (רמת מאמץ, מעבר בין החיבור הישיר
  לשער) — הפעלה מחדש עצלה עם `--resume` על אותו סשן, רגע לפני התור הבא.
- **סרגל סטטוס** חי: מודל · ניצול חלון ההקשר (%) · עלות מצטברת · משך התור האחרון.
- **ניצול מכסת החשבון — תמיד גלוי בפינה השמאלית-תחתונה**: תגית קבועה עם אחוזי
  חלון 5 שעות + שבועי, נמשכת חי מ-`/api/oauth/usage`, מתרעננת כל 30 שנ׳ ואחרי כל תור,
  צבע לפי עומס (כתום מ-70%, אדום מ-90%) + זמן איפוס ב-tooltip.
- **מונה טוקנים חי** — כמות הפלט (וסימון חשיבה) רצה תוך כדי הסטרימינג במחוון "עובד…".
- עצירת תור (Stop), גלילה חכמה עם כפתור "לתחתית", היסטוריית קלט (↑/↓).

### כשהתשובה נעצרת באמצע — עכשיו כתוב למה

עד כה תשובה יכלה להיפסק באמצע משפט בלי מילה אחת של הסבר. זו לא הייתה שתיקה
של ה-CLI: הוא כן מדווח בדיוק למה הוא עצר, אבל בשלושה ערוצים נפרדים שהממשק
זרק את כולם —

1. `system/api_error` — כל כישלון קריאה ל-API, כולל כל ניסיון חוזר
   (`retryAttempt` / `maxRetries` / `retryInMs`). הלקוח טיפל רק ב-`init`
   וב-`thinking_tokens` והתעלם מכל השאר.
2. הודעת `assistant` עם `isApiErrorMessage` — ההודעה הסינתטית "הנה למה עצרתי"
   (`API Error: Response stalled mid-stream`, `529 Overloaded`, סירוב מדיניות).
   היא כן הגיעה למסך ושם נזרקה: המסלול החי מתעלם מכל הודעת `assistant` כי היא
   כפילות של הסטרימינג — וזו ההודעה היחידה שאיננה כפילות אלא ההסבר עצמו.
3. `result` עם `terminal_reason` ≠ `completed` (`api_error` / `stalled` /
   `refusal` / `max_tokens` / `max_turns` / `budget_exhausted` /
   `permission_denied` …) — נקרא רק בשביל העלות והטוקנים.

בנוסף, תהליך שנהרג באות (SIGKILL של מחסל הזיכרון, למשל) הגיע עם `code=null`,
והתנאי שהציג הודעה בדק `if (code && ...)` — כלומר דווקא המקרה השקט ביותר יצא
בשקט מוחלט.

מה שיש עכשיו:

- **כרטיס עצירה בתמליל.** כל סיום שאיננו תקין מייצר כרטיס עם כותרת בעברית,
  הסבר קצר מה לעשות, והטקסט המקורי של ה-CLI בתוך `<details>`. הכרטיס **נשמר
  בקובץ השיחה** — חוזרים לשיחה למחרת והוא עדיין שם, ליד המשפט הקטוע.
- **חיווי "מנסה שוב" בזמן אמת.** בזמן שה-CLI מנסה שוב, מחוון "עובד…" אומר
  `שגיאת API — מנסה שוב (1/3)…` במקום להיראות כמו תקיעה. הוא נשלח גם ב-`sync`,
  כך שטלפון שנפתח באמצע ניסיון חוזר רואה את הסיבה מיד.
- **עצירה שהמשתמש יזם** (Stop, `interrupted`, `cancelled`) מוצגת ככרטיס אפור
  שקט ולא כשגיאה אדומה.
- **מיצוי מכסה לא מוצג פעמיים** — הוא כבר מקבל פס משלו, ולכן הוא לא מייצר
  גם כרטיס.
- **כל עצירה נכתבת ליומן** יחד עם המודל, `terminal_reason`, `stop_reason`,
  סטטוס ה-HTTP והכלים שנדחו.

### יומן ריצה — מסך

היומן (`~/.claude/rtl-claude/rtl-claude.log`) מאחד את מה שהשרת רואה עם מה
שהדפדפן מדווח, באותו סדר זמנים, שורד אתחול ומסתובב ב-4MB. עד כה הדרך היחידה
להגיע אליו הייתה SSH — כלומר בדיוק לא מהטלפון, שהוא המכשיר שבו רוב התקלות
קורות. עכשיו יש לו מסך: **סרגל הצד → "יומן ריצה"**, לוח הפקודות (Ctrl+K), או
כפתור **"פתח יומן"** שיושב על כל כרטיס עצירה ופותח אותו כשהוא כבר מסונן לרגע
הנכון.

במסך: לשוניות מוכנות (הכול · עצירות ושגיאות · תורות · חיבור וסנכרון), סינון
חופשי בביטוי רגולרי, רענון אוטומטי כל 4 שנ׳ בזמן שהתקלה עוד באוויר, והעתקה
או הורדה כדי לצרף לדיווח.

מה שנרשם עכשיו ולא נרשם קודם: `cli.api_error`, `cli.api_retry`,
`cli.api_error_message`, `cli.rate_limit`, `cli.result` (כולל
`terminal_reason` ו-`stop_reason`), `cli.stderr` (שנבלע לגמרי — לא במסך ולא
ביומן), `cli.raw` (שורת stdout שאיננה JSON תקין), `cli.exit` (כולל האות
שהרג את התהליך ושארית ה-stderr) ו-`turn.halt`.

### ספקי מודלים

בורר המודלים מאחד ארבעה מקורות, וכולם נשלפים חי — אין שמות מקודדים בקוד:

| ספק | מקור המודלים | איך התור רץ |
|---|---|---|
| **Anthropic** (ברירת מחדל) | `GET api.anthropic.com/v1/models` עם ההזדהות של Claude Code | ה-CLI מדבר ישירות מול Anthropic |
| **claude-code-router** | `GET /v1/models` מהשער המקומי | `ANTHROPIC_BASE_URL` → השער, שמתרגם ל-Gemini |
| **OmniRoute** | `GET {OMNIROUTE_BASE_URL}/models` | `ANTHROPIC_BASE_URL` → גשר פנימי שמתרגם Anthropic ⇄ OpenAI |
| **מודלים מקומיים** | `GET {LOCAL_BASE_URL}/models` | `ANTHROPIC_BASE_URL` → אותו גשר, מופע נפרד לכתובת המקומית |
| **Cursor** | `cursor-agent --list-models` | סוכן אחר לגמרי — `cursor-agent` במקום `claude` (ראו למטה) |

התפריט מחולק לקטגוריות לפי **משפחת המודל** ולא לפי השער שמגיש אותו, עם מונה
בכותרת כל קטגוריה: `Claude · חיבור ישיר` (המסלול הישיר, תמיד ראשון), ואחריו
`Gemini · Google`, `Claude · דרך שערים`, `GPT · OpenAI`, `Grok · xAI`,
`GLM · Z.ai`, `DeepSeek`, `Qwen · Alibaba` וכו׳; בסוף `ניתוב אוטומטי`,
`מודלים מקומיים` ו-`מודלים נוספים · <שער>` לכל משפחה שלא זוהתה. כך אותו Gemini
משבעה שערים שונים יושב בקטגוריה אחת, במקום להתפזר בין כותרות כמו `· dva`
ו-`· cfp` שאי אפשר לנחש. הקטגוריה, הסדר והחלוקה נקבעים בשרת (`categorize`
ב-server.js), כך שהם זהים בכל מכשיר. השער עצמו נשאר גלוי בתוך מזהה המודל
(`omniroute/gemini/gemini-3.1-pro-preview`), ושם המקור המלא מוצג במקומות שבהם
המודל מופיע בלי כותרת הקטגוריה לידו — שורת המצב וכרטיסי הדואט.

**חיפוש מודל:** לחיצה על בורר המודל (בסרגל הקלט ובטופס הדואט) פותחת חלונית עם
שדה הקלדה במקום תפריט נפתח — ברשימה של מאות מודלים גלילה איננה דרך למצוא מודל.
כל מילה שמוקלדת מסננת לפי שם המודל, המזהה המלא והקטגוריה, וכולן חייבות להתאים
(`gemini flash`, `opus max`, `חינם`). ↑↓ לניווט, Enter לבחירה, Esc לסגירה;
המודל הפעיל מסומן ב-✓. הרשימה נשפכת לעמודות אנכיות זו לצד זו לפי רוחב החלון
(`column-width`, בלי media query): על מסך רחב ארבע עמודות שמציגות עשרות מודלים
בלי גלילה, על הטלפון עמודה אחת. השם תופס את רוחב העמודה והמזהה המלא יורד
לשורה שמתחתיו, כך ששניהם קריאים. ה-`<select>` המקורי נשאר מקור האמת ורק מוסתר, ולכן
השמירה, השידור בין מכשירים והחלפת המודל באמצע שיחה ממשיכים לעבוד דרכו.

ספק שאינו זמין מדלג בשקט: התפריט פשוט לא מציג את המודלים שלו, ושאר הממשק
עובד כרגיל. המעבר בין ספקים באמצע שיחה עובד כמו כל החלפת מודל — הפעלה מחדש
עצלה עם `--resume`, בלי לאבד הקשר.

#### OmniRoute (תואם OpenAI)

**הרמה — פקודה אחת:**

```bash
npm run dev:all     # מרים את OmniRoute (Docker), ממתין שיהיה בריא, ואז מפעיל את השרת
```

או בנפרד:

```bash
npm run omni:up     # OmniRoute ברקע בלבד
npm start           # הממשק בלבד
```

| סקריפט | מה הוא עושה |
|---|---|
| `npm run dev:all` | מרים את OmniRoute וממתין ל-healthcheck, ואז `node server.js` |
| `npm run omni:up` | `docker compose up -d --wait` |
| `npm run omni:down` | מוריד את המכולות (הנפחים נשמרים) |
| `npm run omni:restart` | הפעלה מחדש של OmniRoute בלבד |
| `npm run omni:logs` | לוג חי של OmniRoute |
| `npm run omni:status` | מצב המכולות |

הרמה ראשונה מושכת את האימג' (~460MB) ולוקחת דקה-שתיים; אחר כך זה כמה שניות.
אם OmniRoute לא עולה, `dev:all` מדפיס אזהרה וממשיך להפעיל את הממשק בלעדיו.

**אימות שזה עובד:**

```bash
curl -s localhost:3000/v1/models | head -c 200          # OmniRoute עצמו עונה
curl -s localhost:4173/api/config \
  | grep -o '"omniroute/[^"]*"' | head -5               # והמודלים הגיעו לממשק
```

בממשק: בורר המודלים אמור להציג עשרות רשומות עם התווית `· OmniRoute`.
בוחרים אחת ושולחים הודעה — התשובה מגיעה בסטרימינג רגיל, עם כרטיסי כלים.
הדאשבורד של OmniRoute עצמו נמצא ב-`http://localhost:3000` (חיבור ספקים, מפתחות,
ניצול מכסות חינמיות).

**מה `docker-compose.yml` מרים:** את האימג' הרשמי `diegosouzapw/omniroute` עם נפח
`omniroute-data` על `/app/data` (הגדרות, מפתחות ספקים ומטמון המודלים שורדים
`down`/`up`), ולצידו `redis` — OmniRoute משתמש בו למגבלת קצב ולמטמון, ובלעדיו
הוא נופל למימוש בזיכרון שהתיעוד שלהם ממליץ נגדו.

> **פורטים:** בתוך המכולה OmniRoute מאזין תמיד על `20128` — זה קבוע באימג'.
> ה-compose ממפה אותו החוצה ל-`OMNIROUTE_PORT` (ברירת מחדל `3000`), ולכן
> `OMNIROUTE_BASE_URL=http://localhost:3000/v1` עובד. משנים פורט? עדכנו את
> שתי השורות ב-`.env` יחד. המיפוי מוגבל ל-`127.0.0.1` ואינו נחשף לרשת.

**הגדרות:** `OMNIROUTE_BASE_URL` (ברירת מחדל `http://localhost:3000/v1`) ו-
`OMNIROUTE_API_KEY` (ברירת מחדל `omniroute-local`). התקנה טרייה של OmniRoute
אינה דורשת מפתח והברירות האלה עובדות כמו שהן; אם הפעלתם אימות בדאשבורד,
העתיקו את המפתח מ-**Endpoints** ל-`.env`.

המודלים מופיעים בתפריט עם התחילית `omniroute/` ותווית `· OmniRoute`; התחילית
מונעת התנגשות עם מודל בעל אותו שם שמגיע ישירות מ-Anthropic, והיא נשלפת לפני
שליחה לספק. מודל שמצהיר שאינו תומך בקריאת כלים מסונן ואינו מוצג — Claude Code
הוא סוכן, ובלי כלים כל תור שלו נכשל.

**זמינות:** `openai-bridge.js` בודק את OmniRoute עם timeout קצר (4 שנ׳) ואינו חוסם
את עליית השרת. אם OmniRoute עדיין עולה — הממשק עולה בלעדיו, והבדיקה חוזרת ברקע
בהשהיה גדלה (2 שנ׳ → 30 שנ׳). ברגע שהוא זמין המודלים נכנסים לתפריט מעצמם, בלי
להפעיל מחדש. אחרי שהצליח הרענון עובר לקצב איטי, שגם קולט ספקים שחוברו בדאשבורד
בזמן שהשרת כבר רץ. `/api/config` קורא את הרשימה מהמטמון ולעולם לא ממתין לרשת.

הלקוח היחיד כאן הוא ה-CLI של Claude Code, והוא מדבר Anthropic Messages API בלבד.
OmniRoute תואם OpenAI, ולכן `openai-bridge.js` מרים **גשר** על `127.0.0.1` בפורט
אקראי: הוא מקבל `POST /v1/messages` מה-CLI, מתרגם ל-`POST /chat/completions`,
ומתרגם את התשובה חזרה. `ANTHROPIC_BASE_URL` של התהליך מצביע על הגשר, ולא על
OmniRoute עצמו. הגישה לגשר מוגנת בטוקן אקראי שנוצר בעלייה.

מה עובר בתרגום:

- **סטרימינג** — chunks של OpenAI → רצף SSE תקין של Anthropic
  (`message_start` → `content_block_*` → `message_delta` → `message_stop`).
  טקסט וחשיבה זורמים מילה-מילה.
- **חשיבה** — `reasoning_content` הופך לבלוק `thinking`, כך שכרטיס החשיבה עובד
  גם עם מודלי OmniRoute. בכיוון ההפוך בלוקי חשיבה נזרקים (אין להם מקבילה ב-OpenAI).
- **כלים** — `tools`/`tool_use`/`tool_result` ⇄ `functions`/`tool_calls`/`role:"tool"`.
  תוצאות כלים מוצאות מהודעת ה-user ונשלחות כהודעות `tool` נפרדות, כפי ש-OpenAI דורש.
- **תמונות** — בלוקי `image` מומרים ל-`image_url` עם data-URI.
- **ספירת טוקנים** — ל-OmniRoute אין `count_tokens`, ולכן הגשר מחזיר אומדן
  במקום 404 שהיה מפיל את התור. השימוש האמיתי מגיע ב-`message_delta` בסוף.

מגבלות: `--effort` לא נשלח למודלי OmniRoute ולמודלים המקומיים (כמו במודלי השער) ובורר המאמץ נעלם
עבורם. ארגומנטים של קריאת כלי נצברים ונפלטים כבלוק שלם בסוף במקום לזרום —
ב-Anthropic מותר בלוק פתוח אחד בכל רגע, ואילו OpenAI רשאי לפזר `tool_calls`
בסדר כלשהו. הכלי ממילא אינו רץ לפני שהארגומנטים שלמים.

#### מודלים מקומיים (LM Studio / Ollama / vLLM)

כל שרת תואם-OpenAI ברשת המקומית מתחבר דרך אותו גשר של OmniRoute — `openai-bridge.js`
הוא ספק גנרי, ו-`loadProviders()` מרים ממנו מופע לכל כתובת. ברירת המחדל מצביעה
על שרת ה-LM Studio ברשת:

```bash
LOCAL_BASE_URL=http://192.168.1.253:1234/v1   # כולל /v1
LOCAL_API_KEY=local                            # שרת מקומי לרוב לא מחייב מפתח
# LOCAL_TIMEOUT_MS=600000                      # תור בודד; מודל גדול על חומרה צנועה
```

המודלים מופיעים בתפריט עם התחילית `local/` והתווית `· מקומי`, לצד מודלי
OmniRoute ו-Anthropic באותה רשימה. מודלי הטמעה (`*embed*`) מסוננים — הם אינם
יודעים לשוחח, והופעתם בתפריט רק הייתה מזמינה בחירה שנכשלת.

שרת שאינו רץ (או מחשב כבוי) אינו מפריע לכלום: המעקב פשוט לא ימצא מודלים,
והתפריט עולה בלעדיהם. ברגע שהשרת עולה הם נכנסים מעצמם, בלי להפעיל מחדש.
`LOCAL_BASE_URL=` ריק מכבה את הספק לגמרי.

בדיקה מהירה:

```bash
curl -s 192.168.1.253:1234/v1/models | head -c 200   # השרת המקומי עונה
```

> כל תור רץ מהמחשב שמריץ את `server.js` אל הכתובת הזו ברשת המקומית, בלי
> אימות ובלי הצפנה — בדיוק כמו המאזין ה-LAN של הממשק עצמו. אל תפנו את
> `LOCAL_BASE_URL` לכתובת שאינה ברשת שלכם.

### הגדרות סביבה

`server.js` טוען `.env` מתיקיית הפרויקט אם הוא קיים (בלי חבילה חיצונית).
משתנה שכבר מוגדר בסביבה תמיד גובר. ראו `.env.example` לרשימה המלאה:
`PORT`, `RTL_HOST`, `REMOTE_PORT`, `CCR_GATEWAY_URL`, `OMNIROUTE_BASE_URL`,
`OMNIROUTE_PORT`, `OMNIROUTE_API_KEY`, `OMNIROUTE_TIMEOUT_MS`,
`OMNIROUTE_IMAGE_TAG`, `OMNIROUTE_MEMORY_MB`, `LOCAL_BASE_URL`, `LOCAL_API_KEY`,
`LOCAL_TIMEOUT_MS`.

`docker compose` קורא את אותו `.env` בעצמו, ולכן `OMNIROUTE_PORT` משפיע גם על
מיפוי הפורט של המכולה.

### עבודה מהטלפון — אותה שיחה, מסונכרנת מלא

הטלפון אינו עותק של השיחה אלא **מסך נוסף על אותה שיחה**. אין שני מסדי נתונים
שמסתנכרנים ואין קונפליקטים לפתור: התהליך והזרם חיים בשרת, ושני המכשירים מקבלים
את אותו זרם אירועים בדיוק ומריצים עליו את אותה לוגיקת בנייה.

- **שליחה משני הצדדים** — הודעה שנשלחה מהטלפון מופיעה מיד במחשב ולהפך, כולל
  הסטרימינג מילה-מילה, כרטיסי הכלים, ה-diff וכרטיס החשיבה.
- **התור לא נקטע** — סגירת החלון או נעילת הטלפון כבר לא הורגת את התהליך. אתה
  מתחיל תור במחשב, קם מהכיסא, וממשיך לעקוב מהטלפון באמצע.
- **חזרה מדויקת אחרי ניתוק** — כל פריים מקבל `seq`, והשרת שומר יומן של התור
  הנוכחי. בהתחברות מחדש הקליינט מבקש השלמה מה-`seq` האחרון שראה ומקבל בדיוק
  את מה שהחמיץ. מכשיר שנכנס באמצע תור מקבל את התור השלם מתחילתו.
- **כרטיסי הרשאה ושאלות** — נענים מכל מכשיר, ונסגרים בשני המסכים עם אותה תשובה.
- **אישור מתוך ההתראה** — בקשת אישור שמגיעה לטלפון נושאת `אשר` ו`דחה` בתוך
  ההתראה עצמה. הלחיצה עובדת כשהאפליקציה סגורה לגמרי: אין דף ואין WebSocket,
  אבל ה-service worker חי ושולח את התשובה ב-HTTP. גוף ההתראה נושא את שם הכלי
  ואת הפקודה או הקובץ — כפתור אישור בלי זה הוא בקשה לאשר משהו לא ידוע.
  `AskUserQuestion` לא מקבלת כפתורים: התשובה שלה היא בחירה מתוך אפשרויות.
  הכפתורים נגישים במגירת ההתראות גם כשהמסך נעול, ולכן יש להם מתג נפרד
  בהגדרות — אפשר לכבות אותם בלי לכבות את ההתראות.
- **המסך לא נכבה באמצע** — כל עוד יש תור רץ ואתה מסתכל, הדפדפן מתבקש לא
  לכבות את המסך. ברגע שהלשונית מוסתרת הנעילה משתחררת מעצמה, ולכן אין מסך
  שנשאר דלוק בכיס; היא נלקחת שוב בחזרה ללשונית אם התור עוד רץ.
- **רטט** — שתי נקישות כשמשהו ממתין לך, אחת קצרה כשהתור נגמר. כבוי יחד עם
  ההתראות, באותו מתג.
- **שיתוף אל תוך השיחה** — האפליקציה מופיעה בתפריט השיתוף של המערכת: צילום
  מסך, קטע טקסט או קישור מכל אפליקציה אחרת נכנסים ישירות לשדה הכתיבה
  ולצירופים. התמונות נוסעות למודל כ-base64, בדיוק כמו הדבקה או גרירה.
- **הבוררים והטיוטה** מסתנכרנים גם הם (מודל, מאמץ, מצב הרשאות, תיקיית עבודה).
  טיוטה נכנסת רק לשדה ריק בצד השני, כדי לא למחוק טקסט שמוקלד באותו רגע.
- **כותב אחד לדיסק** — השרת בוחר מכשיר אחראי לכתיבה (זה שממנו שלחת אחרון).
  בלי זה שני המכשירים היו דוחים זה את כתיבתו של זה ומאלצים טעינה מחדש באמצע
  סטרימינג. בדיקת גרסה (`rev`) נשארת כרשת ביטחון.
- תגית בסרגל העליון מראה כשמכשיר נוסף צופה באותה שיחה.

### חיבור מכשיר קבוע (LAN)

הכפתור `מכשירים מקושרים` בסרגל העליון (או ב-Ctrl+K) מציג קוד QR ולצידו **קוד
קצר** בן שמונה תווים (`XXXX-XXXX`). סורקים או מקלידים פעם אחת — וזהו, המכשיר
מקושר לתמיד.

- הממשק מונגש **ברמת ה-LAN**: מאזין נוסף עולה על כתובת ה-LAN של המחשב
  (`192.168.x`/`10.x`/`172.16-31.x`), בפורט `PORT+1`. כל מי שנמצא ברשת
  המקומית — ישירות או דרך VPN שמנתב אליה — מגיע לכתובת הזו. **אין פורט פתוח
  לאינטרנט** ואין שרת מתווך.
- המאזין עולה על כתובת אחת בלבד ולא על `0.0.0.0`: ממשקי docker וגשרים
  וירטואליים לא נבחרים לעולם, כך שקונטיינר שרץ על המחשב לא רואה את הממשק.
  `RTL_HOST` כופה כתובת אחרת, `REMOTE_PORT` כופה פורט.
- **חומת אש:** הפורט צריך להיות פתוח למכונות שברשת המקומית. בפדורה, זון
  `FedoraWorkstation` פותח כברירת מחדל `1025-65535/tcp` ולכן לא נדרשת פעולה.
  אחרת: `sudo firewall-cmd --add-port=4174/tcp --permanent && sudo firewall-cmd --reload`.
- האימות הוא שכבה משלנו: כל מכשיר מקושר מקבל טוקן קבוע בעוגייה `HttpOnly`.
  בדיסק (`~/.claude/rtl-claude/devices.json`) נשמר רק ה-hash שלו, כך שהקובץ
  עצמו אינו מפתח כניסה. כל בקשה, כולל ה-WebSocket, נחסמת בלי טוקן תקף.
- קוד הקישור חד-פעמי ותקף לעשר דקות. **אפשר לקשר ולנתק גם ממכשיר שכבר
  מקושר**, לא רק מהמחשב עצמו — כדי לצרף מחשב שני לא צריך לקום וללכת למחשב
  האם. מכשיר מקושר ממילא שולט ב-Claude ובכלים שלו כאן, ולכן ההגבלה הקודמת לא
  הוסיפה ביטחון אמיתי. הרשימה מציגה מי קישר כל מכשיר, וניתן לנתק כל אחד מהם.
- **שתי דרכים לצרף מכשיר:** לסרוק את ה-QR, או — כשאין מה לסרוק, מחשב מול
  מחשב — לפתוח במכשיר החדש את כתובת ה-LAN ולהקליד שם את הקוד הקצר. הקוד עצמו
  ניתן לשליחה בהודעה או להכתבה בטלפון: הא״ב שלו בן 30 תווים ובלי `0/O/1/I/L/U`
  שמתבלבלים בקריאה, והקלט מתקבל גם באותיות קטנות וגם בלי המקף.
- קוד קצר מספיק כדי להכתיב הוא גם קוד שאפשר לנסות לנחש, ולכן עשרה ניסיונות
  כושלים **שורפים אותו** וצריך לבקש חדש. שמונה תווים מא״ב בן 30 הם ≈39 ביט,
  כך שגם בלי התקרה ניחוש בתוך עשר דקות אינו מציאותי.
- מי שמחזיק במכשיר מקושר מקבל שליטה מלאה ב-Claude ובכלים שלו על המחשב שלך.

אם למחשב אין בכלל כתובת LAN, החלון יציג הודעה מתאימה ולא יאפשר לקשר מכשיר.
שאר הממשק עובד רגיל.

### Remote Control של Claude Code (`/rc`)

`/rc` בתפריט הפקודות פותח את **לוח הניהול של Remote Control** — הפיצ'ר של Claude
Code עצמו, שמחבר את המחשב הזה ל-[claude.ai/code](https://claude.ai/code)
ולאפליקציית Claude בנייד. משם פותחים סשנים שרצים כאן, על הקבצים האמיתיים, **גם
מחוץ לרשת הבית**. זה לא אותו דבר כמו [חיבור מכשיר קבוע (LAN)](#חיבור-מכשיר-קבוע-lan),
שהוא הממשק הזה ברשת המקומית.

- ב-CLI `/rc` מציירת מסך אינטראקטיבי משלה ואינה חלק מזרם ה-`stream-json` — אי
  אפשר פשוט לשלוח אותה לתוך השיחה. לכן היא פקודת-לקוח: הפאנל מריץ בשרת
  `claude remote-control` בתיקייה שנבחרה, קורא את המסך שלו ומציג אותו כאן.
- **מופע לכל תיקייה.** אפשר להריץ עד שישה במקביל, וכל אחד מהם הוא "סביבה"
  נפרדת ברשימה שב-claude.ai. לכל מופע מוצגים המצב, התיקייה, הקיבולת
  (`בשימוש/מקסימום`), אופן פתיחת סשן חדש, הקישור לסביבה, QR לפתיחה מהטלפון
  (נוצר בשרת, בלי לטעון כלום מהאינטרנט), יומן הריצה, וכפתור ניתוק. יש גם
  "נתק הכל".
- **אפשרויות הפעלה** (מתחת ל"אפשרויות…"): שם הסביבה, `--spawn` (סשן חדש באותה
  תיקייה / ב-worktree משלו / סשן יחיד), `--capacity`, `--permission-mode` שבו
  ירוצו הסשנים שנפתחים מרחוק, `-c` (המשך הסשן האחרון שנרשם בתיקייה), וביטול
  הסשן שנפתח מראש (`--no-create-session-in-dir`). התיקייה נבחרת בשדה או בבורר
  התיקיות שבתוך הפאנל.
- **מה רץ בכל מופע** — המסך של ה-CLI מפורסר כפריימים שלמים (הוא מצייר את עצמו
  מחדש בכל שינוי), ומתוכו מוצגת רשימת הסשנים שנפתחו מ-claude.ai: כותרת, מה כל
  אחד עושה כרגע, וקישור לפתיחתו. סשן שנסגר נעלם מהרשימה מעצמו.
- **כל סשן claude חי על המחשב** מוצג בתחתית הפאנל עם התיקייה שבה הוא יושב, מתי
  עלה, ה-PID והמקור שלו — Remote Control, הממשק הזה, או טרמינל. אלה הנתונים
  שה-CLI רושם ב-`~/.claude/sessions/<pid>.json`, מאומתים מול `/proc` כדי
  שתהליך שנפל או PID ממוחזר לא יוצגו כסשן חי. זה גם המקום היחיד שיודע *באיזו
  תיקייה* יושב סשן — במצב `worktree` לכל סשן יש תיקייה משלו. אפשר לסנן לסשנים
  של Remote Control בלבד, ואפשר לסגור סשן בודד (SIGTERM, אחרי אישור); השרת
  מוודא שה-PID מופיע ברשימה החיה, כך שאי אפשר להרוג דרכו תהליך שרירותי.
- התהליכים משותפים לכל הממשק (לא לשיחה בודדת) ונסגרים יחד עם השרת — כדי
  שהמחשב לא יישאר "מחובר" ב-claude.ai אחרי כיבוי.
- **תיקייה מהימנה:** ה-CLI מסרב לרוץ בתיקייה שלא אושרה בדיאלוג האמון שלו
  (`Workspace not trusted`), ול-`remote-control` אין מסך שיציג את הדיאלוג — הוא
  פשוט נופל. לכן הפאנל בודק מראש: אם התיקייה לא אושרה, הוא מסביר זאת, מציג את
  הנתיב המדויק, והכפתור הופך ל**"אשר את התיקייה והפעל"**. האישור מסמן
  `hasTrustDialogAccepted` לתיקייה ב-`~/.claude.json` (קריאה-שינוי-כתיבה אטומית,
  בדיוק כמו שהדיאלוג בטרמינל היה עושה) ומיד מפעיל. אין אישור אוטומטי — רק
  בלחיצה, ורק על התיקייה שמוצגת.
- אם ההפעלה נכשלת מסיבה אחרת, המופע נשאר ברשימה עם שורות השגיאה האחרונות
  מהתהליך, עד שמסירים אותו.
- **זו יציאה החוצה:** מרגע שהוא מחובר, מי שנכנס לחשבון ה-Claude שלך יכול להריץ
  סשנים על המחשב הזה. לכן הוא לא עולה מעצמו — רק בלחיצה מפורשת.

### התקנה על מסך הבית

הממשק הוא PWA: בטלפון פותחים את הכתובת ובוחרים "הוסף למסך הבית", ומקבלים
אפליקציה עם אייקון, בלי סרגל כתובת. באנדרואיד יש גם כפתור `התקן` בהגדרות —
כרום מציע התקנה בבאנר משלו, בתזמון שלו; הכפתור לוקח ממנו את ההזמנה ומעביר
אותה למקום שבו מחפשים אותה. בספארי אין API להתקנה, ולכן שם ההגדרות מציגות
את ההוראות הידניות.

לחיצה ארוכה על האייקון פותחת קיצורים ישירים: **שיחה חדשה** ו**דואט**.

ה-service worker קיים כדי לאפשר את ההתקנה, לשמור את הקליפה (HTML/CSS/JS),
לקלוט שיתופים מאפליקציות אחרות ולטפל בלחיצות על ההתראות — **לא** לעבודה בלי
רשת: Claude, הקבצים והכלים נמצאים על המחשב, ובלי חיבור אליו אין מה להריץ.
קריאות API והזרם החי לא נכנסים למטמון לעולם.

### Cursor — סוכן שני באותו ממשק

בבורר המודלים יושבת קבוצה `Cursor · סוכן CLI` (מחולקת לפי משפחה: `· Claude`,
`· GPT · Codex`, `· Grok`, `· Composer`…). בחירת מודל משם מחליפה את **הסוכן
שרץ**, לא רק את המודל: התור מורץ ב-`cursor-agent` במקום ב-`claude`. הכול נשאר
במקומו — סטרימינג, כרטיסי חשיבה וכלים, דיפים, תור פרומפטים, ריבוי מכשירים,
שמירה לדיסק, חיפוש וייצוא.

**איך זה עובד.** `cursor-bridge.js` הוא שכבת תרגום, ובה כל ההבדל. ה-CLI של
Cursor שונה מזה של Claude בשלושה דברים שקבעו את המבנה:

1. **הוא חד-פעמי.** אין לו `--input-format stream-json`, ואין תהליך שיושב
   ומחכה לתור הבא — כל פרומפט הוא הרצה חדשה, וההקשר משוחזר ב-`--resume <chatId>`.
   לכן מה שהגשר מחזיר אינו תהליך אלא *חיקוי* של תהליך: אובייקט שמתנהג כמו
   `child process` אחד לאורך כל השיחה, ומתחתיו מתחלפים תהליכים לפי תורות.
2. **סכמת האירועים שלו אחרת** (`thinking/delta`, `tool_call/started`,
   `editToolCall`…). התרגום לסכמת Claude נעשה כולו בשרת, ולכן **בדפדפן אין ולו
   ענף אחד שמפצל בין שני הסוכנים**.
3. **אין לו פרוטוקול הרשאות אינטראקטיבי במצב `--print`.** כלי שדורש אישור פשוט
   *נדחה*, בלי שאלה. לכן ההרשאות שם נקבעות מראש בדגלי ההרצה — ראו הטבלה למטה.

**בורר המודלים.** ‎--list-models‎ מחזיר 223 שורות, אבל אין שם 223 מודלים: רמת
המאמץ ותג ה-‎fast‎ אפויים בתוך המזהה (`gpt-5.3-codex-low-fast`). הגשר מכווץ אותם
חזרה לשני הצירים שמהם הורכבו — **78 מודלים בבורר, ומהם 46 עם בורר מאמץ** בדיוק
כמו מודלי Claude. ‎fast‎ נשאר שורה משלו כי הוא מסלול ולא עוצמה.

**מצבי הרשאות של Cursor** (הבורר מתחלף אוטומטית עם המודל, והבחירה נזכרת לכל
סוכן בנפרד):

| מצב | דגל | מה זה באמת עושה |
|---|---|---|
| **הרץ הכול** (ברירת מחדל) | `--force` | מריץ כל כלי בלי לשאול |
| **אישור חכם** | `--auto-review` | מסווג בשרת מריץ קריאות בטוחות; השאר נדחה |
| **רשימת היתר בלבד** | *(ללא)* | רק מה שב-`~/.cursor/cli-config.json`; השאר נדחה |
| **פתיחה בתכנון** | `--mode plan` | מצב *התחלה* בלבד |
| **פתיחה בשאלות** | `--mode ask` | מצב *התחלה* בלבד |

> `plan` ו-`ask` הם מצבי פתיחה, **לא גדרות**: לסוכן יש כלי `SwitchMode` והוא
> משתמש בו. בבדיקה הוא יצא ממצב תכנון וכתב את הקובץ שהתבקש. התוויות נוסחו כך
> בכוונה — "תכנון בלבד" היה מבטיח כאן משהו שלא מתקיים.

**כשכלי נדחה.** ל-`cursor-agent --print` אין כרטיס אישור חי — הוא פשוט דוחה,
והמודל מנסה שוב עד שהוא מוותר. לכן כרטיס הכלי נצבע **"נדחה"** (צהוב, לא אדום —
זו החלטה ולא תקלה) ומציג שני כפתורים: **"אשר תמיד · Shell(touch)"** שכותב חוק
קבוע ל-`~/.cursor/cli-config.json`, ו-**"עבור ל'הרץ הכול'"**. החוק חל מהתור
הבא. הדחייה נשמרת בתמליל, ולכן הכפתור עדיין שם גם אחרי רענון.

> פקודות שהוא מסווג כקריאה-בלבד (`ls`, `whoami`) רצות גם ב"רשימת היתר בלבד"
> בלי שהן מופיעות בה.

**מה עובד, ומה לא:**

- ✅ **`--resume`** — כולל החלפת מודל *ורמת מאמץ* של Cursor באמצע שיחה, חי, בלי
  לאבד הקשר ובלי להפעיל מחדש.
- ✅ **תמונות** — ל-`--print` אין קלט תמונות כבלוק, אבל יש לו כלי שקורא קובץ
  תמונה ורואה אותו. התמונה נכתבת לתיקיית הזמניים של השרת (אותו ניקוי לפי TTL)
  והפרומפט מפנה אליה בנתיב.
- ✅ **תפריט `/`** — מציג את ה-Skills של Cursor (`~/.cursor/skills-cursor`,
  ו-`.cursor/skills` של הפרויקט) במקום פקודות Claude שלא היו קורות שם.
- ✅ **תיקייה חדשה** מסומנת כמהימנה אוטומטית (`--trust`).
- ✅ **"סשנים על הדיסק"** מציג את שיחות Cursor של התיקייה עם כותרת ומניין תורות
  (נקראים מתוך `store.db`), ופאנל ה-MCP מציג גם את שרתי Cursor.
- ✅ **שרשור פרומפטים, קטיעה, ריבוי מכשירים, דואט** — עובדים כרגיל.
- ⚠️ **חזרה לנקודה קודמת (rewind)** — אין ל-Cursor פיצול סשן לא-הרסני. הממשק
  מציע במקום זאת, בשאלה מפורשת: לחתוך את התמליל ולהתחיל סשן חדש מהנקודה —
  **בלי ההקשר הקודם**.
- ⚠️ **צ׳אט אנונימי** — חסום: אין ל-Cursor מקבילה ל-`--no-session-persistence`,
  והוא כותב כל שיחה ל-`~/.cursor/chats`. הבטחה שאי-אפשר לקיים לא מוצגת.
- ℹ️ **מד המכסה** בסרגל הוא של Anthropic ואינו משקף שימוש ב-Cursor.
- ℹ️ **מזהי סשן אינם חוצי-סוכן.** מזהה של Claude אינו קריא ל-Cursor ולהפך, ולכן
  החלפת סוכן באמצע שיחה פותחת סשן חדש במקום ליפול על `No conversation found`.
  שיחה של Cursor מסומנת בתג `Cursor` ברשימת השיחות.

## מצבי הרשאות

- **אישור עריכות** (ברירת מחדל) — מריץ ומתיר עריכות קבצים.
- **תכנון בלבד** — מתכנן ולא משנה כלום (מצוין לשחק עם התצוגה).
- **רגיל** — התנהגות ההרשאות הרגילה.
- **ללא בקשות** — מריץ הכול בלי לעצור (זהירות).
- **⚡ GOD** — מאשר הכול *ומראה בדיוק מה אושר*. הבורר נצבע בסגול כשהוא פעיל.

### ⚡ GOD — אישור אוטומטי עם יומן

`god` אינו מצב של ה-CLI אלא של הממשק, וזה ההבדל שלו מ"ללא בקשות":

| | ללא בקשות (`bypassPermissions`) | ⚡ GOD |
|---|---|---|
| מי מחליט | ה-CLI לא שואל בכלל | ה-CLI שואל על **הכול**, השרת עונה "אשר" |
| מה נשאר אחרי | כלום | שורה על כל בקשה, עם הקלט המלא שלה |

בפועל ה-CLI מופעל ב-`--permission-mode default` — המצב שבו כל כלי שאינו ברשימת
ההיתר נעצר ושואל — והשרת עונה `behavior: allow` תוך פריים אחד, בלי כרטיס ובלי
להמתין למכשיר כלשהו. כל אישור כזה משודר כפריים `god_allow`, וכשהתור נגמר הוא
נסגר ל**כרטיס אחד מקופל בסוף ההודעה**: כפתור "⚡ GOD · N בקשות אושרו אוטומטית",
ומתחתיו כל בקשה ככרטיס הכלי המוכר — פקודת Bash מלאה, diff של עריכה, נתיב של
כתיבה. הכרטיס הוא חלק מהתמליל, ולכן הוא נשאר שם אחרי רענון ובמכשיר השני.

החריג היחיד הוא `AskUserQuestion`: אין לה "אישור", יש לה תשובה, ו"אישור אוטומטי"
בלי תשובה היה מחזיר למודל שאלה ריקה. היא ממשיכה להופיע ככרטיס רגיל.

מעבר ל-GOD באמצע ריצה עונה גם לכרטיסים שכבר פתוחים באותו רגע, כדי שלא יישארו
תלויים. בזמן שהתור רץ, הפס "עובד…" מונה כמה בקשות כבר אושרו.

### פיצ'רים חזקים — הנגשת פונקציות הטרמינל

- **אישור הרשאות אינטראקטיבי בתוך ה-UI** — כשמצב ההרשאות דורש אישור, מופיע כרטיס
  עם תצוגת הפעולה (פקודה / diff / נתיב) וכפתורי **אשר · אשר תמיד · דחה**. מבוסס על
  `--permission-prompt-tool stdio`: ה-CLI שולח `can_use_tool` בערוץ ה-stream-json,
  ואנחנו עונים ב-`control_response`. "אשר תמיד" מוסיף חוק הרשאה קבוע.
- **מענה על שאלות של Claude** — כש-Claude שואל שאלה (כלי `AskUserQuestion`) מוצג
  כרטיס אמיתי: כותרת, האפשרויות עם ההסבר לכל אחת, ריבוי-בחירה כשצריך, תצוגה
  מקדימה, ואפשרות **"אחר…"** לניסוח חופשי. התשובה חוזרת ל-CLI בתוך
  `updatedInput.answers` — המקום שבו הוא מצפה לקבל תשובות מרכיב ההרשאות.
  קודם לכן השאלה הוצגה ככרטיס "אשר/דחה" עם JSON גולמי, בלי שום דרך לענות עליה.
- **אישור תוכנית** — `ExitPlanMode` מוצג כתוכנית מעוצבת (Markdown) עם
  **אשר והתחל לעבוד / המשך לתכנן**, במקום JSON.
- **שאלה לא יכולה להיעלם** — כרטיסי שאלה נשמרים כחלק מהתמליל, ולכן שורדים מעבר
  בין שיחות ורינדור מחדש. בנוסף מופיע פס בולט **"Claude ממתין לתשובה"** עם כפתור
  קפיצה לשאלה, וכשהחלון ברקע — סימון בכותרת והתראת שולחן עבודה.
- **פקודות סלאש** — הקלדת `/` פותחת תפריט: פקודות מובנות (`/clear`, `/compact`,
  `/init`, `/review`, `/rc`…) ופקודות מותאמות אישית שנסרקות מ-`.claude/commands` (פרויקט + אישי).
- **אזכור קבצים `@`** — הקלדת `@` פותחת בורר קבצים חי מתיקיית העבודה (מסנן
  `node_modules`/`.git` וכו׳), עם ניווט מקלדת, ומכניס `@path` להקשר.
- **סשנים על הדיסק** — עיון בסשנים קודמים של Claude Code בתיקייה (כותרת + זמן +
  מספר תורות) והמשכם עם `--resume`.
- **פאנל MCP** — רשימת שרתי ה-MCP המחוברים והסטטוס שלהם (מ-`claude mcp list`).
- **תמונות** — צירוף מהדיסק לפי נתיב, גרירה, והדבקת צילום מסך (נשמר זמנית ונמחק).

## איך זה עובד

`server.js` מחזיק את השיחות, והדפדפנים הם צופים. תהליך `claude` שייך ל**שיחה**
(`conversationId`) ולא לחיבור: הוא לא נולד ולא מת עם טאב, וכל החיבורים שצופים
באותה שיחה מנויים על אותו זרם. כל פריים יוצא מקבל `seq` עולה ונשמר ביומן של
התור הנוכחי, וזה מה שמאפשר השלמה מדויקת אחרי ניתוק במקום להתחיל מאפס.

> קודם לכן כל חיבור WebSocket החזיק תהליך משלו ו-`ws.close` הרג אותו. כלומר
> שני מכשירים = שני תהליכים ושני עותקי תמליל שדרסו זה את זה בדיסק, וסגירת
> הטאב בטלפון קטעה תור שרץ.

הפרוטוקול מול הדפדפן: `subscribe` (עם `sinceSeq`) → `sync` שמכריז `catchup`
(דלתא מהיומן) או `reset` (קרא את השיחה מהדיסק, ואז קבל את התור הרץ מתחילתו),
ואחריו זרם `event` / `user_msg` / `busy` / `permission` / `presence` / `ui`.

אותו יומן הוא גם ההגנה על **מנוי שלא מספיק לנקז**. עם `--include-partial-messages`
כל טוקן הוא פריים נפרד לכל מנוי, וטלפון על סלולר חלש לא קורא אותם בקצב שבו
הם נכתבים — בלי תקרה, התהליך היה צובר אותם בזיכרון בלי גבול. סוקט שעבר את סף
ההמתנה פשוט מפסיק לקבל, ומסומן ב-`seq` האחרון שיצא אליו; כשהוא מתנקז, אותו
מסלול `catchup` משלים לו את הפער לפי הסדר. פיגור ארוך מהיומן נופל ל-`reset`.

לכל שיחה מופעל:

```
claude --print --input-format stream-json --output-format stream-json \
       --include-partial-messages --replay-user-messages --verbose \
       --permission-mode <mode> --permission-prompt-tool stdio \
       [--model M] [--effort E] [--resume SID]
```

מיד עם ההפעלה נשלחת לחיצת-יד `initialize` (control_request) שמפעילה את ערוץ
ההרשאות. השרת מפענח את אירועי ה-JSON ומשדר אותם לכל המכשירים המנויים, כולל
בקשות הרשאה (`can_use_tool`) שמנותבות ככרטיסי אישור. כרטיס פתוח נשמר בשרת,
כך שמכשיר שמתחבר עכשיו רואה אותו ויכול לענות עליו. הדפדפן מרנדר את הכול
(marked + DOMPurify + highlight.js + mermaid — הכול מוגש מקומית, בלי אינטרנט).

בקשת `control_request` מסוג שהממשק לא מכיר כבר לא נענית מיד בשגיאה — היא מוצגת
למשתמש, ורק אם לא נענתה תוך 5 דקות השרת עונה בשגיאה כדי שה-CLI לא ייתקע.

נקודות קצה נוספות: `/api/files` (אזכור קבצים), `/api/sessions` (סשנים על הדיסק),
`/api/mcp` (שרתי MCP), `/api/commands` (פקודות סלאש).

Remote Control: `/api/rc/status` (כל המופעים + כל סשני claude החיים על המחשב),
`/api/rc/start` (מחזיר 409 עם `needsTrust` כשהתיקייה לא אושרה), `/api/rc/stop`
(עם `cwd` — מופע אחד, בלעדיו — הכל), `/api/rc/session/stop` (סוגר סשן לפי PID
שמופיע ברשימה החיה), `/api/rc/qr?cwd=` (SVG), ו-`/api/rc/trust` (GET בודק אם
התיקייה מאושרת, POST מאשר אותה).

חיבור מכשירים: `/api/remote/status`, `/api/remote/pair` (יוצר קוד),
`/api/remote/qr` (SVG), `/api/remote/unpair`, `/api/remote/cancel-pair` —
כולן מוגבלות לבקשות מהמחשב עצמו.

אחסון השיחות (כתיבה נושאת `baseRev`, ו-409 מחזיר את הגרסה שבדיסק במקום לדרוס):
`/api/store` (אינדקס + הגדרות), `/api/conversations/:id`
(GET/PUT/DELETE), `/api/settings`, `/api/flush` (שמירה סופית ב-sendBeacon),
`/api/import` (הגירה חד-פעמית מ-localStorage), `/api/search` (חיפוש בכל השיחות).
